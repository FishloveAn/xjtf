### S2 · Director 简化导演（压力值 → 刷怪节奏）

**目标**：Director 每 0.5s 算压力值 `pressure ∈ [0,1]`，按公式驱动 spawn_interval 缩放，数据全部在 director.json（tech-plan §7.3）。

**验收标准**（对应冒烟清单新增 E4）：
- E4 压力节奏生效：场上丧尸少/玩家倒地（存活占比低）→ pressure 升高 → spawn_interval 变短（刷怪变快）；改 `data/director.json` 权重/上下限重启后生效。
- pressure 更新频率 0.5s；`spawn_interval = base_interval * (1.6 - pressure)`，结果钳制在 min_s/max_s；`pressure = clamp(0.4*(1-存活玩家占比) + 0.3*(1-场上丧尸/上限) + 0.3*(本波已过时间/期望时长), 0, 1)`。
- M2 无特感：`specials.enabled=false`，结构占位不触发。
- **复杂度低可并入 S1**：若 S1 实现已含刷怪节奏，S2 只加压力计算 + director.json 读取，半天内并入（本卡仍单列以便验收 E4 可独立追踪）。

**涉及文件**（res://）：
- 新增 `scripts/gameplay/director.gd`（pressure 计算 + spawn_interval 输出给 WaveManager）
- 读取 `data/director.json`（**本预制作已交付草案**）
- 改动 `scripts/gameplay/wave_manager.gd`（刷怪节奏改由 Director 提供；S1 先用 waves.json.spawn_interval 兜底）
- 调试：HUD 或输出面板显示 pressure / 当前 spawn_interval（E4 可观测）

**依赖**：S1。**顺序：2（可与 S1 合并为 S1'）**

### S3 · 丧尸群 30 只（对象池 + MultiMesh + 分帧联动）

**目标**：同屏 30 只丧尸主机 60 FPS：对象池消除反复 instantiate/free，渲染走 MultiMesh 合并（或简化方案兜底），AI 分帧预算联动（tech-plan §5.1/§5.4/§5.5）。

**验收标准**（对应冒烟清单新增 E5）：
- E5 同屏 30 只：用第 3 波配置或调试命令刷满 30 只，主机 60 FPS 不卡（帧率监视器可查）；丧尸部分 draw call ≤ 20；连杀 30 只后 Zombies 容器子节点数回落（对象池复用，无泄漏、无瞬时 instantiate/free 卡顿）。

- 单机无红色 Error；扩展 `tests/scenes/test_zombie_ai.tscn` 或新增加压场景刷 30 只验证性能。

### S4 · 物资系统简化版（补给点：弹药 + 医疗）

**验收标准**（对应冒烟清单新增 F1-F4）：
- F1 主场景有弹药补给点 + 医疗补给点（标识模型/发光提示，摆放位置可编辑）。
- F2 靠近按 E → `request_pickup`（any_peer）→ 服务器校验距离/补给点状态 → 结算：弹药补给点 = 当前武器备弹/弹匣补充（简化：备弹 +1 或补满弹匣），医疗补给点 = 目标玩家 +50 HP（上限 max_hp）；结果经 authority 广播，所有端一致；HUD 提示拾取结果。

## 4. 数据草案说明（交付 2，本预制作已落盘）

### 4.1 `data/waves.json`（S1/S3 读取）

- 3 波配置：**试探（common 10）→ 警戒（common 18）→ 潮涌（common 30）**；composition 单波总和 ≤30（M2 同屏目标），末波峰值 30 恰好覆盖"同屏 30 只"验收。
- 字段严格照 tech-plan §7.2：`id / name / composition / concurrent_cap / spawn_style / spawn_interval / cleared_when / reward`。
- `concurrent_cap` = 该波同屏上限；波 1（10/10）、波 3（30/30）全量在场，波 2（18/12）渐进刷怪体现"上限 < 总量"的节奏。
- `cleared_when` M2 统一 `all_spawned_killed`（全部刷出且杀光）；不做时间/目标点类型。
- `reward` 先占位：S4 以**静态补给点**为主，`reward` 字段预留为 Intermission 补货的数值来源（后续可让奖励转化为补给点库存）。
- 数值均为 L4D 类常识初值，**待平衡**（note 字段标注）。

### 4.2 `data/director.json`（S2 读取）

- 压力参数照 tech-plan §7.3：3 项权重（player_alive 0.4 / zombie_depletion 0.3 / time_elapsed 0.3）、`spawn_interval = base * (max_scale - pressure)`（max_scale 1.6）、结果钳制 min_s/max_s、更新频率 0.5s。
- 特感结构**占位**：`specials.enabled=false`（M2 无特感），threshold 0.7 / max_simultaneous / cooldown_s 留给 M3。
- 预留降级开关 `degrade`（tech-plan §11 风险 1：同屏超阈值自动削减刷怪），M2 可关。
- 数值均为常识初值，**待平衡**。

### 4.3 数据纪律

- 两份 JSON **纯数据、无代码引用**，安全；S1/S2 起由 WaveManager/Director 读取，改数值不改代码（tech-plan §2.2 规则 3）。

## 5. M2 风险备注（实现时最容易踩的 5 个坑）

1. **MultiMesh 顶点动画在 4.7 实测风险**（tech-plan §12 知识缺口 3）
   MultiMeshInstance3D 顶点着色器动画理论成立但需实测。M2 对策：**30 只先保证"数量 + 性能"达标，动画观感是加分项**——若 4.7 顶点动画翻车，用简化方案（低模静态/淡出）兜底，不阻塞 S3 验收；美术侧 500-1200 tris 低模 + 顶点色通道（R 腿/G 臂/B 头躯干）已与 art-director 对齐（tech-plan §10.1），MultiMesh `set_instance_custom_data()` 写相位/速度/变体种子做摆动。

2. **对象池实现注意（避免反复 instantiate/free）**
   tech-plan §5.5：反复 instantiate/free 是 100 只丧尸卡顿头号元凶。M2 死亡流程改 `despawn_to_pool`：**复位 hp/state/碰撞层/位置/速度 + 隐藏 + 出组**；`zombie_died` 广播后的血雾/淡出仍走本端表现，淡出结束回池而非 queue_free。**回池复位不彻底 = 第二次出池出现"死尸复活/碰撞残留"**，S3 验收 E5（连杀 30 只无泄漏 + 表现正常）必须覆盖。

3. **30 只性能预算（主机 60 FPS 第一优先，tech-plan §10）**
   AI 分帧已就位（`MAX_AI_PER_FRAME=40` 验证 30 只）；渲染走 MultiMesh 后丧尸部分 draw call ≤20；物理：30 只 CharacterBody 在 Jolt 的表现需 M2 实测（引擎版本记录知识缺口 3），若物理成为瓶颈再评估（如碰撞只在服务器开）。**先做 30 只性能冒烟**（tech-plan §11 风险 1 缓解路径：30 → 记录帧率曲线）。

4. **丧尸同步方案（M1 Synchronizer → 30 只是否需快照）**
   M1 每只丧尸用 `ZombieSync`（Synchronizer，20Hz）。30 只规模带宽估算 ≈ 30 × ~20B × 20Hz ≈ **12 KB/s/客户端**，局域网可接受 → **Synchronizer 方案 M2 够用**；但 30 只 × 30 个 Synchronizer 的消息数与主机 CPU 需在 **S5 联机实测**——若 4 人下抖动/CPU 超标，再评估提前上自定义快照（tech-plan §5.3，原归 M3）。另注意**对象池与 MultiplayerSpawner 复制机制冲突**（池化隐藏节点不随 add_child 复制）：S3 需决策「服务器权威池 + 客户端本地池复用」或「Spawner 直连 + 池化仅服务器侧」，决策落地记入 `03-开发-引擎版本记录.md`。

5. **API 先查官方类参考（M0/M1 教训延续）**
   M2 新用到：`MultiMesh` / `MultiMeshInstance3D` / `set_instance_transform` / `set_instance_custom_data` / 对象池相关；生成代码前查 4.7 官方类参考确认存在与参数，**别凭记忆写 API 名**；新踩的 API 注意点即时补录 `03-开发-引擎版本记录.md`。
