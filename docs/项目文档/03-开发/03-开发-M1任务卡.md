## 0. M1 范围与依赖链（一句话）

> **单机"开枪 → 击杀丧尸 → 倒地救援"战斗闭环可玩 + 双人联机战斗同步跑通**（阶段说明 M1 验收）。

依赖链（对照 tech-plan 附录 B 顺序：2 玩家控制器 → 3 武器 → 4 伤害接口 → 5 丧尸 AI）：

```
S1(伤害接口+玩家血量) ─┬─> S2(倒地/救援/复活)
                       ├─> S3(武器基类+手枪 hitscan) ─> S4(霰弹枪)
                       └─> S5(丧尸三态AI) ─> S6(命中反馈+死亡表现)
S3 / S5 / S6 ────────────────> S7(音效接线 P0 + 单机/联机闭环验收)
S5 / S6 ─(可选)────────────> S8(波次最小版 3 波，默认顺延 M2 开篇)
```

> 注意：伤害接口（damageable/hitbox）是武器与丧尸的公共底座，必须先于二者落地（附录 B 第 4 项虽列在武器之后，但那是"写脚本"顺序；按依赖它应先行，本卡已调整，理由见 §4 备注）。

## 2. Story 明细（每 Story 半天粒度，黄金闭环 tech-plan §8.1）

### S1 · 伤害接口 + 玩家血量（服务器权威）

**目标**：建立全项目统一伤害接口（damageable/hitbox），玩家有服务器权威血量与极简 HUD 血条；武器与丧尸后续都走同一接口结算。

**验收标准**（对应冒烟清单新增 C1 / D2）：
- C1 玩家出生 100 HP，HUD 显示血条；受击（临时调试按键或命令扣 20）血条下降并广播到所有端。
- 统一接口可用：`core/damageable.gd` 提供 `take_damage(dmg, attacker)` 与 `damaged / died` 信号，**服务器权威**；`core/hitbox.gd` 提供命中区域（collision_layer=3）挂接 damageable。
- D2 双人联机：A 的 HUD 能看到 B 掉血（MultiplayerSynchronizer 或服务器广播）。
- 单机无红色 Error（A1 回归）。

**涉及文件**（res://）：
- 新增 `scripts/core/damageable.gd`（接口 + 信号）
- 新增 `scripts/core/hitbox.gd`（命中区域）
- 新增 `scripts/player/player_state.gd`（Health 部分：hp/max_hp、take_damage、同步；后续 S2 在同一文件扩状态机）
- 改动 `scenes/player/player.tscn`（加 Health 节点 + 同步属性，注意 4.7 SceneReplicationConfig 先 add_property 再设模式）
- 新增 `scenes/ui/hud.tscn` + `scripts/ui/hud.gd`（极简血条；UI 只读状态不持有游戏状态，tech-plan §3.1）
- 改动 `scenes/main/main.tscn`（挂 HUD）

**依赖**：无（前置条件：M0 冒烟 A 组全过）。**顺序：1**

### S2 · 玩家状态机：倒地 → 救援 → 复活

**目标**：血量归零进入"倒地"而非直接死亡，队友可救援复活；倒地后再次受击或长期无人救援 → 死亡。

**验收标准**（对应冒烟清单新增 C5 / D3）：
- C5 玩家 HP=0 → 倒地状态：移动禁用、视角保留、有"倒地"标识（模型姿态/HUD 提示）。
- 队友走到倒地玩家身边按交互键（E）→ 救援进度 3 秒 → 复活（HP 恢复至 50）。
- 倒地后再次受击 → 死亡（M1 简化：倒地玩家淡出/黑屏提示；完整死亡结算归 M2）。
- D3 双人联机：A 倒地，B 按 E 救援成功，A 复活两端可见。
- 服务器权威：救援判定走 RPC（`request_revive` → 服务器计时 → `revive_done` 广播），客户端不本地改状态。

**涉及文件**（res://）：
- 改动 `scripts/player/player_state.gd`（状态机 ALIVE/DOWN/DEAD，RPC 入口 + 同步）
- 改动 `scenes/player/player.tscn`（倒地姿态/交互检测区域）
- 新增 `scripts/player/revive_area.gd`（交互检测，或并入 player_state）
- 改动 `scripts/ui/hud.gd`（倒地提示 + 救援进度条）

**依赖**：S1。**顺序：2**

### S3 · 武器基类 + 手枪 hitscan 射击

**目标**：手枪可开火：射速/弹药/换弹/hitscan 命中，伤害走 S1 接口，服务器复判（tech-plan §6.2、§4.3）。

**验收标准**（对应冒烟清单新增 C2 / D2）：
- C2 手枪：鼠标左键开火，弹匣 -1；打空后自动换弹或按 R 手动换弹；HUD 显示弹药（如 `9 / 12`）；射速受 `fire_rate` 限制（5.0 发/秒）。
- 开火即播本地枪声/枪口火花（视觉层本地立即响应，不依赖服务器）。
- 服务器复判：客户端 `rpc_id(1, "request_fire", origin, dir, target_id)` → 服务器在**服务器物理空间** `intersect_ray` 复判 → 命中走 `take_damage` → `apply_damage` 广播；未命中只扣弹药。
- 数据全部来自 `data/weapons.json`（改 JSON 数值立即生效，无硬编码）。
- D2 双人：A 开枪打丧尸，B 端看到丧尸同步掉血/死亡。

**涉及文件**（res://）：
- 新增 `scripts/weapons/weapon_base.gd`（读 weapons.json、fire/reload、弹药状态、RPC 入口）
- 新增 `scripts/weapons/hitscan.gd`（服务器物理空间复判，`PhysicsDirectSpaceState3D.intersect_ray`）
- 新增 `scenes/weapons/weapon_base.tscn` + `scenes/weapons/pistol.tscn`
- 读取 `data/weapons.json`（**本预制作已交付草案**）
- 改动 `scenes/player/player.tscn`（WeaponPivot 挂枪，tech-plan §3.2）
- 改动 `scripts/player/player_controller.gd`（开火/换弹输入）
- 改动 `scripts/ui/hud.gd`（弹药显示）

**依赖**：S1。**顺序：3**

**目标**：霰弹枪可用：一次开火射出多颗弹丸（散射），近距离爆发伤害，与手枪共享武器基类。

### S5 · 丧尸场景 + 三态 AI（追踪/攻击/死亡）

**目标**：普通丧尸可生成、追踪玩家、近战攻击（伤害走 S1 接口），三态 AI + 简化导航 + 分帧预算（tech-plan §5.4）。

**验收标准**（对应冒烟清单新增 C4）：
- C4 丧尸生成后向最近玩家直线移动（每 1.5s 重算朝向 + CharacterBody 撞墙物理）；玩家跑出 `chase_range` 停止追击回 Idle。
- 进入 `attack_range` → 近战攻击：前摇 → 命中玩家扣血（走 damageable），攻击有冷却。
- HP 归零 → Dead 状态（停止移动/碰撞；死亡表现由 S6 完成）。
- 独立调试场景 `tests/scenes/test_zombie_ai.tscn`：刷 10 只验证 AI 分帧预算生效，主场景保持 60 FPS。

## 4. 备注：伤害接口为什么放在 S1（对齐附录 B）

tech-plan 附录 B 的书写顺序是"写脚本"顺序（4 在 3 之后），但**依赖**上伤害接口是武器（扣丧尸血）与丧尸（扣玩家血）的公共底座。本卡把 damageable/hitbox 提前到 S1，与玩家血量一并落地，S3/S5 各自只做消费方——避免两处各自实现"扣血"造成重复代码（控制清单：core 层不重复实现）。

## 5. data/weapons.json 草案说明（预制作交付 2）

- 文件：`data/weapons.json`（本预制作已交付，S3 起读取）。
- 武器条目字段严格照 tech-plan §6.2：`id / damage / fire_rate / mag_size / reload_time / spread_deg / range_m / auto / sound / muzzle_offset`。
- 扩展字段（已预留）：`name_zh`（中文显示名，HUD/切枪用）；`pellets`（霰弹单次散射弹丸数，仅霰弹枪有；S4 读取并按 pellets 循环多射线）。
- 顶层结构：`{ "version", "note", "weapons": [...] }`——留好后续加武器/加字段的空间（如后续步枪可加 `auto: true`、`pellets: 1`）。
- 初值均为 L4D 类常识值，**待平衡**（标注在 JSON note 字段）。设计侧建议：普通丧尸血量 100（zombies.json 在建时），则手枪 4 枪/只、霰弹近身 1 枪/只。
- MVP 简化：霰弹换弹为整体换弹（单数值 reload_time），不做 L4D 逐发装填。

## 6. M1 风险备注（实现时最容易踩的 3 个坑）

1. **API 名称/调用顺序要查官方类参考（M0 教训延续）**
   M0 已踩：`SceneReplicationConfig` 必须先 `add_property()` 注册再设 replication mode；`sync_interval` 应为 `replication_interval`。M1 将新用到 `MultiplayerSpawner`（丧尸生成）、`PhysicsDirectSpaceState3D.intersect_ray`（hitscan 复判）、`GPUParticles3D`、`AudioStreamPlayer3D` 等 API。**生成代码前先查 4.7 官方类参考确认存在与参数，别凭记忆写 API 名**；新踩的 API 注意点即时补录 `03-开发-引擎版本记录.md`。

2. **hitscan 服务器复判注意点（tech-plan §4.3 / §6.2）**
   客户端只发 `request_fire(origin, dir, target_id)`；服务器**必须在服务器物理空间重新 `intersect_ray` 复判**（防"打空气"作弊），并校验弹药余量/射速冷却/目标存活；射线 query 要 `exclude` 射手自身与错误碰撞层；伤害结算只走服务器（`apply_damage` 广播），客户端绝不本地扣血；`get_remote_sender_id()` 校验来源（§4.4）。

3. **丧尸 AI 分帧预算（tech-plan §5.4）**
   同屏 30 只时每帧全量更新 AI 会卡主机（主机卡 = 全员卡）。每帧最多更新 N 只（如 40）其余轮询；普通丧尸**禁止 NavigationAgent3D**（直线朝向 + 每 1.5s 重算 + CharacterBody 撞墙）；LOS 检测只对近距/分帧做，不做每只每帧 raycast；死亡即 `queue_free` 防节点堆积（对象池归 M2）。
