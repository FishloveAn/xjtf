# 音频方向文档（Audio Direction）

- **项目**：L4D-like · Godot 4 · 局域网 4-8 人 · 第一人称 PVE FPS（丧尸潮 + 合作求生）
- **作者**：阮和鸣（audio-director）｜**日期**：2026-08-04
- **定位**：音频是"氛围放大器"，不是核心玩法。一人开发、无音频经验 → 本档**务实、轻量、可执行**，后期打磨阶段再深入，方向现在就定死，避免返工。
- **原则**：先搭系统、再填内容；素材优先现成免费包，不自己造声音；音频内容可后期整体替换，**总线与触发结构现在就要对**。

---

## 1. 音频基调（3-4 句定调）

- **音乐**：紧张、压抑的工业/氛围垫（低音 drone + 稀疏脉冲），**不写旋律性强的"曲子"**——低频持续层自带紧张感、且天然避开版权风险；危机时刻（尸潮警报）叠加"警报脉冲"提紧张度，平时压低让位给音效。
- **音效**：粗粝写实、偏"机械 + 血肉"质感——枪声重低频"砰"与短促爆破感，丧尸嘶吼用**多层人声 + 失真/降调处理**（低频咆哮 + 高频尖啸分层），不追求超真实，要的是"绝望求生"的颗粒感。
- **环境**：低频风声/废墟底噪做持续"无声胜有声"的衬底，脚步区分地表材质（水泥/泥土/金属），警报与尸潮提示是环境里唯一的"高频事件声"。
- **一致性**：全游戏听觉统一在"工业废墟 + 绝望求生"，响度归一（目标 -18 ~ -12 LUFS），任何素材入库先做响度对齐，避免个别声音突兀。

## 3. 免费素材策略

### 3.1 推荐站点（按省心程度排序）

1. **Kenney.nl（Kenney Audio）**——全套 **CC0**（可商用、可改、无需署名），音效+音乐都有，**第一选择**。先下整套，游戏立刻有声音。
2. **freesound.org**——最大免费音效库，**用搜索过滤选 CC0**；枪声/丧尸人声嘶吼这类"拟真向"素材这里最全。
3. **OpenGameArt.org**——游戏美术+音频混站，许可混杂（CC0/CC-BY/GPL），**下载前必看许可标签**。
4. 补充：**Sonnis（CC0）**、**Zapsplat（免费账号 + 署名）**、**Godot Asset Library**（部分内置音频包）。

### 3.2 版权注意点（一人开发也要记）

- **CC0**：最安全，可商用可修改，无需署名。→ 优先选。
- **CC-BY**：可商用可修改，**必须署名**。→ 在 `CREDITS/audio-sources.md` 里统一登记"素材名 + 作者 + 来源链接 + 许可"。
- **❌ 禁用**：CC-BY-NC（非商用）、CC-BY-ND（禁止修改）、GPL 音频——游戏要分发即违规。
- **下载即记账**：任何素材入库当天写进 `CREDITS/audio-sources.md`，一次性登记避免后期补账噩梦。

### 3.3 AI 生成音效可行性

- **可行场景**：丧尸嘶吼、怪物类"非现实存在"的声音——无版权参照物，AI 生成反而安全且省事；氛围垫/过渡音效也可。
- **可用工具**：ElevenLabs（音效/语音生成，付费版可商用）、Stable Audio、AIVA（音乐）。
- **⚠️ 谨慎点**：
  1. **商用许可查 TOS**：ElevenLabs 付费档生成内容可商用；免费档/部分平台生成内容禁止商用或归属模糊，**付费档 + 保留生成记录**才安全。
  2. **AI 音乐（Suno/udio 等）版权争议大**：只用于 P2 打磨期的临时垫底，正式音乐仍用 CC0 或手工拼氛围层。
  3. **质量参差**：AI 音效适合 P2 补变体，**不适合 P0 核心依赖**（核心枪声/丧尸声先上现成包，保证节奏稳定）。
  4. 生成后统一做**响度归一化**（见第 4 节），否则混音失衡。

## 4. Godot 4 音频实现要点

### 4.1 节点选型

| 场景 | 节点 | 要点 |
|---|---|---|
| 3D 空间音效（枪声/丧尸/脚步/受击） | `AudioStreamPlayer3D` | 挂到产生声音的实体上；调 `max_distance`（默认 2000 太长，设 40-80m）、`unit_size`（1.0）、`attenuation_model`（默认对数衰减即可） |
| 队友脚步/远处尸潮 | `AudioStreamPlayer3D` | 距离衰减让玩家能"听声辨位" |
| UI 音效 / 菜单 | `AudioStreamPlayer`（非 3D） | 不衰减、全局播放 |
| 音乐（BGM） | `AudioStreamPlayer` | 单例（autoload）持有，跨场景不中断 |
| 环境底噪循环 | `AudioStreamPlayer`（2D 全局）或 3D | 建议 2D 全局，避免"远离声源听不到" |

### 4.2 音量总线（Audio Bus）——现在就要建好

```
Master（-0 dB，末尾挂 Limiter 防爆）
 ├─ Music（默认 -8 ~ -6 dB，压住让位给音效）
 ├─ SFX （默认 0 dB，主战场）
 ├─ Ambient（默认 -6 dB，环境底噪）
 └─ UI  （默认 -3 dB）
```

- 总线结构**现在建好**，后期只填内容，不用改结构。
- 音量设置（滑条 → `AudioServer.set_bus_volume_db`）存到设置文件，**首日就做**，否则打磨期才发现没法调音量。
- Master 挂一个 `Limiter` 效果器，防枪声叠加爆音——这是唯一推荐的默认效果器。

### 4.3 音频格式

- **短音效（枪声/受击/脚步/UI）**：`.wav`（16-bit/44.1kHz）——解码开销低、低延迟、便于做循环点；枪声这种高频同发场景尤其适合。
- **长音频（音乐/环境底噪循环）**：`.ogg`（Vorbis）——体积小，循环播放可接受解码开销。
- 结论：**主推 .ogg 以省体积，但高频短音效用 .wav**；项目小、一人开发，全 .ogg 也能跑，性能瓶颈不在格式而在"同发数"（见 4.5）。

### 4.4 目录与命名约定（交给程基岩实现规格）

```
assets/audio/
  music/     # bgm_menu.ogg, bgm_explore.ogg, bgm_combat.ogg
  sfx/       # sfx_weapon_pistol_fire_01.wav ...
  ambient/   # amb_wind_01.ogg ...
  ui/        # ui_confirm_01.wav ...
  vo/        # 预留（后期本地化配音）
```

命名：`{类型}_{类别}_{名称}_{变体号}.{ext}`，全小写下划线。事件触发用 `AudioStreamPlayer.play()` + `pitch_scale` 随机 ±5% 制造自然差异（**不额外买素材**）。

### 4.5 性能预算（Windows 桌面机，宽松但仍要控）

- **同发语音数**：全游戏峰值控制在 **32-48 个**以内。做法：枪声等高频事件用**播放器池**（预建 8-16 个 `AudioStreamPlayer3D` 循环复用，不每次 `new`）。
- **丧尸嘶吼**：2-4 个循环播放器 + 随机 `pitch_scale` 模拟"多只丧尸"，**绝不给每只丧尸一个循环实例**。
- **内存**：.ogg 音乐每首几百 KB，总量控制在几十 MB 内完全无压力；主菜单音乐单例常驻，战斗音乐按需加载。

## 5. 音频里程碑（配合 MVP → 扩展 → 打磨）

### MVP（先让游戏"听上去成立"）——只做 P0
- 枪声 ×2（手枪 + 霰弹）、丧尸受击/倒地、玩家受击、命中反馈、基础脚步（水泥）、环境底噪循环。
- 系统搭建：**总线结构 + 音量设置 + 播放器池**——这比内容更重要，MVP 必须一并落地。
- 验收标准：单局战斗中"开枪 → 击中 → 丧尸倒地"这条反馈链每个环节都有声，其余可静音。

### 扩展（内容补齐）——P1
- 全武器枪声 + 换弹/空仓、丧尸嘶吼 + 尸潮警报、近战声、UI 全套、菜单/探索/战斗 3 条音乐循环、事件提示音（购买/补给/安全屋）。

### 打磨（音频最后阶段，投入最重）——P2
- 环境细节（雨/雷/地形杂音）、丧尸嘶吼变体库（4+ 变体随机）、动态混音（危机时音乐自动提层）、特殊丧尸音效、击杀连杀提示、AI 生成补充变体、**本地化 VO 预留**（结构上留 vo/ 目录与总线即可，不实际配音）。

## 6. 风险与待办

| 项 | 说明 |
|---|---|
| 音量平衡 | 一人开发无监听环境，**Master 挂 Limiter** + 响度归一化是最低保障；首日做音量设置菜单 |
| 版权混用 | 多站点混素材必须 `CREDITS/audio-sources.md` 逐条记账，CC-BY 不署名 = 违约 |
| 与工程衔接 | 事件命名/触发点清单（本档 4.4 节）交程基岩；丧尸 AI 触发"嘶吼/受击/倒地"的事件时机需与设计/工程对齐 |
| 待用户拍板 | ① 音乐走"纯 CC0 氛围垫"还是"AI 生成氛围垫"；② 枪声是否接受用 Kenney 现成包起步（推荐） |
| 下一步建议 | 等工程文档落地后，产出"音频事件清单（触发条件/优先级/变体）"细表，再排音频里程碑进开发计划 |
