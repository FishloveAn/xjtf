# 领域文档使用规则

本项目采用单领域文档布局。

## 修改前必读

根据任务范围读取以下资料：

1. `docs/CONTEXT.md`：项目领域术语、核心规则和模块地图。
2. `docs/adr/`：与当前改动相关的架构决策记录（索引见 `docs/adr/README.md`，共 8 条定案）。
3. `docs/项目文档/README-总目录.md`：需求、设计、开发、测试、部署和维护文档的唯一入口。
4. 总目录指向的相关专题文档，不要求无差别读取全部资料。

若某条 ADR 尚未建立（决策未明确或已过时），应继续以当前代码与项目文档为准，并把差异明确记录，不凭空推断。

## 术语与事实优先级

- 运行行为以当前代码、场景、数据文件和可复现测试结果为准。
- 产品意图以需求和设计文档为准。
- 已明确的架构取舍以 ADR 为准。
- 文档与实现不一致时必须明确记录差异，不能静默选择其中一方。
- 新文档应链接到现有权威文档，避免复制大段内容形成多份事实来源。

## 目录职责

```text
/
├── AGENTS.md                  # agent 唯一入口（自动读取）
├── CREDITS/                   # 素材来源记账（与 assets 强关联）
└── docs/                      # 唯一文档文件夹
    ├── CONTEXT.md             # 领域术语与模块地图
    ├── adr/                   # 架构决策记录
    ├── agents/                # 开发代理工作规则
    └── 项目文档/              # 完整产品与工程资料
        └── README-总目录.md   # 文档唯一入口
```
