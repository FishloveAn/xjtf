# 音频系统设计 · 使用文档（Audio System Design & Usage）

- **项目**：《星际土匪》（StarBandit）· Godot 4.7.1 + GDScript · Windows 局域网 4-8 人合作 PVE FPS
- **作者**：阮和鸣（audio-director）｜**日期**：2026-08-07｜**版本**：v1.0（系统设计落地，代码已实证）
- **前置文档**：`02-设计-音频方向.md`（基调/素材策略/里程碑）、`02-设计-音频-P0清单-M1.md`（P0 事件映射）；本档是**实现规格 + 使用文档**，事件与参数以本档为准
- **一句话**：音效由「事件表（`data/audio_events.json`）+ 播放器池（`SfxPool`）」驱动——新增音效**只改 JSON 或加同名素材文件**，不碰代码；素材缺失自动静默，就位即出声。

## 1. 系统架构

```
┌─────────────────────────────── 游戏逻辑（触发方，任意端本地调用） ───────────────────────────────┐
│  weapon_base(开火/换弹/空仓)  player_controller(脚步/跳跃/落地/切枪)  player_state(受击/倒地/死亡/救援) │
│  door(开门)  pickup_item/supply_point(拾取)  zombie_ai(嘶吼/受击/死亡)  wave_manager(尸潮警报)  │
└──────────────────────────────────────────┬──────────────────────────────────────────────────┘
                                            │ SfxPool.play_3d("event", pos) / play_2d("event")
┌──────────────────────────────────────────▼──────────────────────────────────────────────────┐
│                              SfxPool（autoload 单例，scripts/audio/sfx_pool.gd）               │
│   ① 事件解析：data/audio_events.json → 事件定义（files/pitch/volume/bus/mode/limit/衰减/loop）  │
│   ② 路由：mode=3d → AudioStreamPlayer3D 池（10 个轮转）｜mode=2d → AudioStreamPlayer 池（4 个）│
│   ③ 播放：随机变体 + pitch 变调 + volume_db + max_distance + 同帧限流（默认 4/帧/事件）          │
│   ④ 容错：素材缺失静默跳过；JSON 缺失回退内置最小表                                          │
└──────────────────────────────────────────┬──────────────────────────────────────────────────┘
                                            │ bus 输出
┌──────────────────────────────────────────▼──────────────────────────────────────────────────┐
│  Audio Bus（default_bus_layout.tres）：Master(-0dB, Limiter) → SFX(0dB) / Music(-6dB) /        │
│  Ambient(-6dB) / UI(-3dB)  —— 音量滑条改各 bus volume_db 即整体调类音量                        │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

**核心设计原则**（延续音频方向 §1/§4）：

1. **事件名驱动**：逻辑层只喊事件名（`"pistol_fire"`），不关心具体文件——音色/音量/衰减全部数据化。
2. **素材缺失静默**：`files` 指向的文件不存在 → 不播、不报错；素材就位（或改名到位）后**无需改代码**即出声。
3. **多变体随机**：`files` 数组随机选一 + `pitch ±范围` 抖动，消除"复读机"感（方向 §4.4）。
4. **同帧限流**：每物理帧每事件最多 `limit` 次（默认 4），防霰弹 8 弹丸、尸潮 80 只同时嘶吼刷爆播放器池。
5. **全端本地播放**：视觉层纪律（tech-plan §4.2）——服务器不结算音效；世界事件（门/拾取/倒地/死亡）经既有 authority RPC 广播到各端，各端本地播 3D。

## 2. 目录结构与命名规范

### 2.1 目录结构

```
assets/audio/
  music/       # BGM 循环（bgm_menu.ogg / bgm_explore.ogg / bgm_combat.ogg，P2 打磨期）
  sfx/         # ★ 音效主目录（本系统所有事件素材）
  ambient/     # 环境底噪循环（amb_wind_01.ogg 等，P2）
  ui/          # UI 音（ui_confirm_01.ogg 等，P1；也可放 sfx/ 下，事件表 bus=UI 即可）
  vo/          # 预留：本地化配音
```

> 事件表 `files` 字段用**相对 `assets/audio/` 的路径**（如 `"sfx/sfx_weapon_pistol_fire_01.ogg"`），与 `weapons.json` 的 `sound` 字段风格一致。

### 2.2 命名规范（延续音频方向 §4.4）

```
{类型}_{类别}_{名称}_{变体号}.{ext}
   │      │      │      │       └ ext：短音效 .ogg（项目当前统一 .ogg；高同发短音可用 .wav 更低延迟）
   │      │      │      └ 变体号：01、02、03（同事件多个随机变体）
   │      │      └ 名称：小写下划线，语义化（fire/reload_start/empty/footstep_concrete/door_open...）
   │      └ 类别：weapon/player/footstep/door/pickup/zombie/wave/ui...
   └ 类型：sfx=音效（当前全部）；bgm=音乐；amb=环境
```

**事件名 = 命名规范的直接产物**：`{类别}_{名称}`（如 `pistol_fire`、`footstep_concrete`、`door_open`）；武器系事件前缀带武器 id（`pistol/shotgun/rifle/smg`）。

## 3. 安装与配置

### 3.1 首次安装（已随本项目就位，无需重复执行）

1. **素材入库**：把 CC0 音效文件拷入 `assets/audio/sfx/`，**按 §2.2 命名规范改名**（变体连续编号 01/02/03）。
2. **响度归一化**（建议）：目标 -18 ~ -12 LUFS（Audacity：效果 → 响度标准化 → -15 LUFS），保证混音不突兀（方向 §1）。
3. **当日记账**：写入 `CREDITS/audio-sources.md`（素材名/作者/来源链接/许可，CC0 也记账——总纲 §7 风险 7 纪律）。
4. **事件表确认**：`data/audio_events.json` 中对应事件的 `files` 指向该文件名（默认已按命名规范写全，通常无需改）。
5. **自测**：`godot --headless --path . --script tools/debug_audio_system.gd`（详见 §9）。

> 新增素材后**不需要**重编译/重启编辑器；运行时 `SfxPool` 按需 `load()` + 缓存，缺失素材就位后下一帧即出声。

### 3.2 事件表配置文件：`data/audio_events.json`

事件表是系统的"音色调音台"。结构：

```jsonc
{
  "version": 1,
  "events": {
    "pistol_fire": {                    // 事件名（逻辑层调用用这个名字）
      "mode": "3d",                     // 播放通道：3d=空间定位（AudioStreamPlayer3D）/ 2d=全局（AudioStreamPlayer）
      "bus": "SFX",                     // 输出总线（SFX/Music/Ambient/UI；默认 SFX）
      "priority": 90,                   // 预留：未来抢位让位用（本次未实现抢占逻辑，仅记录）
      "limit": 4,                       // 同帧同事件播放上限（≤0 不限；默认 4）
      "files": ["sfx/sfx_weapon_pistol_fire_01.ogg",
                "sfx/sfx_weapon_pistol_fire_02.ogg",
                "sfx/sfx_weapon_pistol_fire_03.ogg"],  // 候选变体（相对 assets/audio/），播放随机选一
      "pitch": [0.97, 1.03],            // 变调：float=固定 / [min,max]=随机（制造自然差异与音色区分）
      "volume_db": 0.0,                 // 事件基准音量（dB，相对总线；默认 0）
      "max_distance": 60.0,             // 3d 模式最大可闻距离（米；默认 60，见音频方向 §4.1）
      "loop": false                     // 循环播放（环境/音乐类预留；loop 是 AudioStream 属性，见 §5 注）
    }
  }
}
```

**字段默认值速查**：`mode=3d`｜`bus=SFX`｜`limit=4`｜`pitch=1.0`｜`volume_db=0`｜`max_distance=60`｜`loop=false`。
**可省略字段**：所有字段均可省略（用默认值），但 `files` 必须为非空数组（否则事件不发声）。

### 3.3 音量与衰减参数建议（当前事件表已按此配置）

| 类别 | 音量（volume_db） | 衰减（max_distance） | 依据 |
|---|---|---|---|
| 枪声（主武器） | 0 ~ +1 dB（霰弹最重） | 60 m | 战场主角，可闻距离最远 |
| 枪声（自动武器） | -1 ~ -2 dB | 60 m | 连发压一档防盖过队友 |
| 换弹/空仓 | -1 ~ 0 dB | 40 m | 手感声，中距可辨 |
| 丧尸嘶吼/受击/死亡 | -3 ~ 0 dB | 30-40 m | 敌情警示，中距 |
| 玩家受击/倒地/死亡 | -4 ~ -1 dB | 15-40 m | 受击近距体感，死亡全队可听 |
| 脚步 | **-8 dB** | 20 m | 不能盖枪声，近距辨位 |
| 跳跃/落地 | -6 / -4 dB | 15 / 20 m | 环境细节 |
| 门/拾取/开关 | -3 ~ -2 dB | 15-30 m | 交互确认，近距 |
| 命中确认 | -6 dB | 20 m | 轻巧的"噗/啪" |
| 警报（2D） | 0 dB | —（全局） | 事件声，必须突出 |

## 5. 调用方式（API 参考）

### 5.1 播放接口（SfxPool autoload，全局可调）

```gdscript
SfxPool.play_3d("pistol_fire")                        # 3D 事件，位置默认 Vector3.ZERO（音源附近）
SfxPool.play_3d("door_open", door.global_position)    # 3D 事件，指定世界位置
SfxPool.play_2d("wave_alarm")                         # 2D 事件（全局不衰减；实际通道由事件 mode 决定）
```

> **入口与 mode 的关系**：事件定义 `mode` 决定走 3D 池还是 2D 池；`play_3d`/`play_2d` 两个入口只是语义区分，最终按事件 `mode` 路由——所以 2D 事件用 `play_3d` 调也会正确走 2D 通道（反之亦然）。推荐按语义选入口。

### 5.2 素材容错约定

- 事件未注册（表里没有）→ 静默。
- 事件注册但 `files` 指向的文件不存在 → 静默（素材就位即生效，无需改代码）。
- 事件注册、素材缺失、`limit` 限流触发 → 跳过本次播放。
- **任何情况下不打印 ERROR**（`FileAccess.file_exists` 先查，避免 `load()` 缺失路径红字）。

### 5.3 多人/权威模式下的播放纪律（重要）

| 事件性质 | 播放策略 | 示例 |
|---|---|---|
| 本地即时手感（开火/切枪/脚步/空仓） | **本地直接播**，不等服务器 | `weapon_base._on_fire_visual()` |
| 服务器事件广播后表现 | **收到 authority RPC 才播**（不本地猜，tech-plan §4.4） | `zombie_died`、`hit_confirmed`、`door_open`、`pickup_*`、`player_down/die/revive` |
| 体感声 | **只播给当事人**（`rpc_id(owner_peer_id())`） | `player_hurt` |

> 广播链路已封装在既有代码中（如 `player_state._broadcast_player_down_sound()` 做 `is_network_active()` 旁路：单机直接调用、多人走 RPC）。**新增世界事件音效时**按此模式：服务器结算点 → authority RPC → 各端本地 `play_3d`。

## 8. 扩展方式（新增音效三步走）

### 8.1 新增一把武器（如近战匕首）

1. `data/weapons.json` 加条目（`sound` 字段非必改——事件名由 `weapon_id` 自动推导）。
2. `data/audio_events.json` 加 `melee_swing`、`melee_hit` 事件（或匕首用 `knife_*`）。
3. 素材按命名规范放 `assets/audio/sfx/` → 触发点调用 → 完成。

### 8.2 新增场景材质脚步

1. 在 `player_controller.gd` 的材质关键字数组（`_STEP_MATERIAL_METAL/_DIRT`）加关键字，或在 `_detect_ground_material()` 加匹配分支。
2. 事件表加 `footstep_wood` 等事件（pitch/音量照抄水泥档）。
3. 素材入库即生效。

### 8.3 新增一个可交互物体

```gdscript
# 玩法对象脚本内，触发点一行调用：
SfxPool.play_3d("button_press", global_position)   # 事件名先在事件表注册（files 可先指向不存在路径占位）
```

### 8.4 音乐 / 环境底噪（P2 打磨期）

- 音乐：单独 autoload（如 `MusicPlayer`）持有长循环 `AudioStreamPlayer`，输出走 **Music** 总线（-6dB 压住让位给音效）；3 条 BGM（menu/explore/combat）放 `assets/audio/music/`，战斗时用 `AudioServer.set_bus_volume_db` 或交叉淡入切换（方向 §2.5）。
- 环境底噪：2D 全局 `AudioStreamPlayer`（Ambient 总线，-6dB），`loop=true`（在**素材的 AudioStream 资源**上开循环——4.7 实测 `AudioStreamPlayer` 无 loop 属性，循环是流的属性，见 §3.2 注）。
- 动态混音（危机提层）：`wave_manager` 事件广播处联动音乐 bus 音量。

### 8.5 本地化 VO（预留）

- 结构已留 `assets/audio/vo/` 目录；触发用 2D 全局 + 独立总线，多语言包按 `vo/zh/`、`vo/en/` 子目录切换（素材就位后按 §3.1 记账入库）。

### 8.6 性能预算提醒（方向 §4.5）

- 全游戏同发峰值 ≤32-48：本系统 3D 池 10 + 2D 池 4 轮转，**同发数由 `limit` 兜底**（默认每事件每帧 ≤4，枪声/受击高频事件依赖池轮转打断）。
- 丧尸嘶吼用「2-4 个循环播放器 + 随机 pitch」模拟多只，**不按只数给实例**——当前 `zombie_growl` 事件 + 限流即为此设计。
