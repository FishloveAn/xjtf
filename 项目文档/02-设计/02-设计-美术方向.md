# 美术方向文档（Art Direction）
**项目**：L4D-like 局域网合作 PVE FPS（Godot 4 + Low Poly）
**作者**：林绘澄（art-director）｜**版本**：v1.0｜**日期**：2026-08-04
**前提**：1 人开发、无美术经验、全程 AI 协作 / 免费素材；目标平台仅 Windows；局域网 4-8 人联机；第一人称。

> 本文档是一份「照着做就行」的执行手册，不是灵感集。每个决策都给出理由与可量化的规格，让开发者（你）不需要美术直觉也能保持一致观感。

---

## 0. 总纲：一句话视觉方针

> **「暗夜城市里的明暗戏剧」**：冷色低饱和的废墟环境做底，暖色高饱和的光源/血/补给做强调；敌人用「明度高于背景 + 暖色偏置 + 剪影特征」保证可读性；所有资产遵循统一的「圆润低模 + 纯色/顶点色」语言。

三条不可违背的铁律（违背即视为离题，开发中自检用）：
1. **敌人永远比背景亮**（至少 +25% 明度，见 §6 对比度规范）。
2. **可交互物永远是暖色系**（黄/橙/绿，不用蓝紫，蓝紫留给环境）。
3. **一个物体最多 2 种材质**（纯色底 + 一个强调色块），保证合批与统一感。

## 1. 视觉身份（Visual Identity）

### 1.1 Low Poly 风格定调：推荐「风格化低模（Stylized Low Poly）」

| 选项 | 特征 | 对本项目的评价 |
|---|---|---|
| 写实低模（Realistic Low Poly） | 低面数+PBR贴图+法线/粗糙度 | ❌ 需要贴图功底与光照功底，一人做不划算，且低面数写实很容易变成「廉价感」 |
| **风格化低模（Stylized Low Poly）** | 平面着色（flat shading）、顶点色/纯色、夸张剪影、略圆润几何 | ✅ **推荐**。无需贴图技巧、AI 生成成功率高、GPU 开销低、观感「有意的简洁」而非「做不好」 |
| 卡通低模（Cartoon/Toon） | 描边、赛璐璐色块、夸张比例 | ❌ 描边着色器对无经验者调校成本高，且卡通感与丧尸恐怖基调冲突 |

**理由**（为什么风格化低模是这个项目最大的杠杆）：
1. **零贴图依赖**：纯色材质 + 顶点色即可，省掉 UV 展开、烘焙、贴图绘制的全部学习成本。
2. **AI 生成友好**：主流 AI 生成 3D（Meshy/Tripo 等）产出天然就是风格化低模，几乎不用改风格。
3. **恐怖靠光影不靠细节**：L4D 的恐怖来自黑暗、尸潮密度、音效与节奏，不需要写实建模。
4. **性能冗余**：平面着色 = 每面一个明度，天然便宜，给 20-30 个同屏丧尸留出预算。

**落地开关（Godot 4）**：材质用 `StandardMaterial3D` 打开 **Flat Shading**（或在 Mesh 导入时勾选）；未用贴图时用 `albedo_color` 纯色即可；想加一点立体感就烘焙顶点色（用 Blender 顶点绘制或 AI 生成时已带）。

### 1.2 配色方案

**核心逻辑：冷底 + 暖点（Cold Base, Warm Points）**。冷色压暗环境衬托恐怖，暖色只给「命、伤、可交互、危险」当信号色。

| 色类 | 用途 | 色值建议（HEX，线性偏好） | 说明 |
|---|---|---|---|
| 主色（环境基底） | 墙面/地面/废墟 | 深蓝灰 `#2A3140`、沥青灰 `#3A3F4A`、墨绿灰 `#2E3A33` | 低饱和、偏冷，占画面 60-70% |
| 辅色（环境层次） | 木质件、锈铁、砖、植被 | 木褐 `#6B4A32`、锈橙 `#7A4A2E`、暗砖红 `#5A3330` | 中明度暖灰，占 20-25%，增加层次不抢戏 |
| 强调色（信号色） | 血包、弹药、可交互、危险、特感 | 安全黄 `#FFC93C`、信号橙 `#FF7A2F`、医疗绿 `#3DDC84`、血洋红 `#D94F4F` | 高饱和高亮，占 5-10%，**只用于信号** |
| 敌人偏置色 | 普通丧尸 | 病态暖灰 `#8A7A66`、腐绿 `#7A8A66` | 比背景亮且带一点暖，见 §6 |

**明度对比策略（保证可读性）**：
- 环境明度集中在暗区（L≈15-35%），敌人明度提到 L≈55-75%——敌人永远是最显眼的移动物体。
- 环境内明度差靠「光源照明」制造（灯光照到的区域亮、其余暗），不靠贴图花纹。
- 血/弹等道具使用**自发光（emissive）或高亮材质**，在任何光照下都可见。

### 1.3 光照基调

- **基调**：固定「深夜 + 冷月光 + 人工暖光源」，**MVP 不做昼夜循环**（昼夜循环 = 光照方案要适配两套，成本翻倍且影响尸潮可读性，放到扩展期后再议）。
- **主光**：方向光（月光）——冷色 `#7A8CB8`，低强度（0.3-0.5），**不投阴影或只投近距离阴影**（省性能）。
- **氛围色**：全场景加 **Distance Fog**（距离雾）——雾色取环境主色 `#2A3140`，一来压暗远景隐藏 pop-in，二来统一色调。
- **强调光**：局部点光（灯笼/火光/枪口闪光）——暖色 `#FFB35C`，强度 1.2-2.0，衰减范围小。**枪口火光用短暂点光**是 FPS 手感核心。
- **结果**：画面呈现「大范围冷蓝黑 + 局部暖橙」的经典戏剧性对比，丧尸处于暗背景中天然突出。

## 2. 视觉锚点（Visual Anchors）——AI 生成时统一风格的参照

以下 5 个锚点按优先级排列。**AI 生成资产时，提示词里同时引用锚点 A + 对应品类锚点**，即可保持项目内一致性。

| # | 锚点 | 描述 | 用途 |
|---|---|---|---|
| A | **Quaternius 低模角色**（quaternius.com） | 圆润块状、chunky 剪影、纯色/顶点色、无贴图细节、姿态夸张 | **角色/丧尸的统一模板**。提示词写 "low poly, flat shading, stylized, chunky silhouette, vertex colors, no textures, like Quaternius style" |
| B | **Kenney 资产包**（kenney.nl） | 干净纯色几何块、圆角、像素完美对齐、极简 | **环境/道具/UI 的统一模板**。提示词写 "clean low poly, solid colors, minimal, like Kenney game asset style" |
| C | **《深岩银河》（Deep Rock Galactic）光照氛围** | 暗环境 + 强暖光源 + 冷色补光、明暗戏剧性 | **光照与氛围参照**（只取光照，不取渲染细节） |
| D | **《求生之路 2》场景构成语言** | 安全屋/补给点/尸潮走廊/瓶颈关卡的空间语义、可读的路径引导 | **关卡视觉语义参照**（配合 design-strategist 的关卡设计） |
| E | **类《无主之地》描边（简版）** | 黑色轮廓线提升剪影辨识（可选，打磨期再上） | **特感/关键角色描边**，用 Godot `next_pass`/轮廓 shader 实现 |

**统一提示词模板（给 AI 生成 3D 用）**：
```
[风格锚点A/B]，low poly stylized game asset，flat shading，[纯色|顶点色]，chunky silhouette，
single object，[品类：humanoid zombie / weapon / prop]，no background，no text，
[颜色：主色+强调色]，facing forward，isometric-friendly proportions，glb/obj export
```

## 3. 资产清单与规格（核心交付物）

### 3.0 通用规格（所有资产都遵守）

- **文件格式**：3D 一律 `.glb`（glTF 二进制，Godot 4 原生导入最佳）；UI 用 `.svg`；贴图 `.png`（尺寸为 2 的幂：256/512/1024）。
- **单位/轴**：Godot 默认单位 = 1 米；模型 Y 轴向上，角色面朝 +Z 或 -Z（统一选 **面朝 -Z**，Blender 导出时校正）。比例以「门高 2.4m、人高 1.8m」为基准。
- **材质数**：每模型 ≤ 2 种材质（见总纲铁律 3）。
- **命名规范（全局）**：`品类_名称_变体序号`，全小写 snake_case，无空格无中文。
  - 角色：`char_survivor_male_a`、`zombie_common_01`、`zombie_special_hunter`
  - 武器：`wep_pistol_01`、`wep_shotgun_01`、`wep_rifle_01`、`wep_melee_crowbar`
  - 环境块：`env_block_wall_01`、`env_block_road_01`、`env_prop_car_01`
  - 道具：`prop_medkit_a`、`prop_ammo_01`、`prop_molotov_01`
  - UI：`ui_crosshair_01`、`ui_icon_medkit`、`ui_icon_special_hunter`
  - 特效：`fx_blood_splat_01`、`fx_muzzleflash_01`
- **目录结构（assets/ 下）**：
  ```
  assets/
    characters/    # 幸存者 + 丧尸（含动画 .glb）
    weapons/       # 武器（world + view 两个场景）
    environment/   # 环境模块块 + 大件
    props/         # 道具
    ui/            # 图标/准星/主题
    vfx/           # 粒子材质/贴花/着色器
    maps/          # 关卡场景 .tscn
  ```

### 3.1 角色（Characters）

| 资产 | 数量建议 | 三角面预算 | 贴图/材质 | 备注 |
|---|---|---|---|---|
| 幸存者角色 | **4 个**（2 男 2 女，可换肤复用） | 2,500-4,000 tris/个 | 纯色材质 + 少量顶点色 | 共用一套骨架（humanoid），动画一套跑全 |
| 普通丧尸·基础网格 | **2 个**（瘦型 + 壮型） | **500-1,200 tris/个**（瘦型 600-1,000 / 壮型 800-1,200，硬上限 1,200） | 纯色材质 + 顶点色（顶点色通道用作**动画区域掩码**，见下） | 每个网格做 3-4 套换皮（材质色变体）；**顶点动画友好设计**：肢体粗壮、四肢区域顶点色掩码清晰、关节枢轴自然 |
| 普通丧尸·变体 | **4-6 个换皮**（灰皮/腐绿/焦黑/血污 + 配饰：安全帽/破警服/断臂） | 复用基础网格 | 换材质 albedo_color 变体 + 附加小件（≤200 tris） | **换皮不换网** = 渲染合批友好（§7）；皮肤区分走材质变体，顶点色留给动画掩码 |
| 特感·Hunter（跳跃者） | 1 | 2,000-3,000 tris | 纯色 + 强调色块 + 轻微 emissive | 瘦小、弓背、四肢长——剪影独特 |
| 特感·Boomer（自爆者） | 1 | 2,000-3,000 tris | 纯色 + 强调色块 + emissive 脓包 | 胖大、驼背、圆润——剪影独特 |
| 特感·Tank（坦克） | 1 | 3,000-4,500 tris | 纯色 + 强调色块 | 巨大、宽肩、手掌厚 |
| 特感·（可选第 4 种） | 1 | 2,000-3,000 tris | 同上 | 建议 Spitter（吐酸）/Smoker（舌拉），二选一 |

> **动画（已按工程口径对齐）**：**普通丧尸 = 无骨骼 + 顶点着色器动画**（MultiMesh 实例化，行走摆动/手臂晃动用 shader 按顶点色掩码驱动，GPU 侧执行、零 CPU 成本；用实例 custom_data 的相位偏移避免整群同步摆动）。**骨骼动画仅保留给特感与玩家**（humanoid，来源 Mixamo / Quaternius 自带动画）。普通丧尸模型按「顶点动画友好」设计：肢体粗壮（变形不露馅）、四肢区域用顶点色通道（R=腿/G=臂/B=头躯干）做区域掩码、关节枢轴点位于自然关节处。骨骼动画环节仍是特感/玩家模块的最大风险（见 §4.4）。

### 3.2 武器（Weapons，至少 3 类）

每把武器 = **world 模型（掉地上/其他玩家看到）+ view 模型（自己手里看）**，可复用同一网格（view 可稍高面数）。

| 武器类 | 示例 | 世界模型 tris | 备注 |
|---|---|---|---|
| 近战 | 撬棍/棒球棍/消防斧 | 400-900 tris | 挥砍动画复用 |
| 手枪 | 9mm | 600-1,200 tris | 手感基准武器 |
| 霰弹枪 | 泵动霰弹 | 1,200-2,000 tris | 近距离尸潮主力 |
| 步枪 | 突击步枪/冲锋枪 | 1,200-2,200 tris | 中距离 |
| 投掷物（可选） | 燃烧瓶/管状炸弹 | 300-600 tris | 搭配爆炸特效 |

> 材质：金属用灰 + 一个强调色（如枪身橙/蓝），纯色即可，不需要金属 PBR 细节。**强调色 = 玩家识别武器品级的信号**（近战=灰、手枪=黄、霰弹=橙、步枪=蓝）。

### 3.3 环境（Environment，模块化场景块）

**策略：模块化 kit（Modular Kit）**，像乐高块一样拼地图，避免做整张地图（无法复用、AI 也难出）。

| 资产 | 数量建议 | 三角面预算 | 备注 |
|---|---|---|---|
| 街道块（人行道+马路） | 2-3 个 | 200-500 tris/块 | 含碰撞，GridMap 铺设 |
| 墙面块（完整/破损/门窗洞） | 4-6 个 | 100-300 tris/块 | 破损 = 洞 + 破口边 |
| 建筑块（一层屋/二层屋外壳） | 3-5 个 | 800-2,000 tris/块 | 外立面即可，内部可进则另做室内 |
| 楼梯/斜坡/平台 | 2-3 个 | 100-400 tris/块 | 垂直移动 |
| 掩体（车/沙袋/路障） | 4-6 个 | 300-800 tris/个 | 战术走位 |
| 室内件（桌/柜/床/门） | 6-10 个 | 100-500 tris/个 | 丰富室内场景 |
| 灯光件（路灯/灯笼/电箱） | 3-4 个 | 100-300 tris/个 | 挂点光，暖色 |
| 远景件（剪影楼/烟囱） | 3-5 个 | 200-600 tris/个 | 只做剪影，放雾里 |

> **碰撞体**：所有环境块自带简化碰撞（Godot 里用 `TrimeshCollisionShape` 或对盒子/石块用 `ConvexPolygonShape`）。**绝不用复杂网格碰撞**（性能杀手）。

| 资产 | 数量建议 | 规格 | 备注 |
|---|---|---|---|
| 准星 | 3-4 个变体 | SVG，矢量 | 静态点 + 扩散态 + 命中态（见 §5.2） |

### 3.6 特效（VFX）

| 特效 | 实现方式（Godot 4） | 规格 | 备注 |
|---|---|---|---|
| 血液粒子 | `GPUParticles3D` | 单次 burst 10-25 个粒子，粒子=小球 mesh，寿命 0.3-0.8s | 命中/死亡时喷出 |
| 血液贴花 | `Decal` 节点 | 512×512 血渍贴图（可用程序生成），叠加上限 8-12 个/区域 | 尸体处/溅射处 |
| 枪口火光 | 广告牌精灵（billboard） + 短暂点光 | 64×64 火焰贴图 + PointLight（0.05-0.1s） | 用 Sprite3D 面向相机，两帧循环即可 |

| 尸体消失 | 材质淡出 | 死亡 20-30s 后 `transparency` 渐隐 1-2s | 避免尸体堆叠穿模 |
| 特感出场提示 | 屏幕提示 + 音效（配合 audio-director） | HUD 图标 + 淡入 | 特感剪影图标 |
| 爆炸/火焰（投掷物） | GPUParticles3D + 点光 + 音效 | 25-50 粒子 | 扩展期 |

## 4. 素材获取策略（一人 + AI，三条路并行）

### 4.1 路线对比与推荐

| 路线 | 成本 | 质量/一致性 | 学习曲线 | 适用 |
|---|---|---|---|---|
| **A. 免费资源站（首选）** | 免费 | 高、风格统一（同一作者） | 极低 | 环境/道具/基础角色 |
| B. AI 生成 3D | 低（API 计费） | 中、需挑选与清洗 | 中 | 特感/定制武器/氛围件 |
| C. CSG/程序化 | 免费 | 中低、够用 | 极低 | 关卡原型、灰盒 |

**明确推荐：以 A（免费资源站）为主力，C（CSG）搭关卡原型，B（AI）只补缺口。**

理由：无美术经验者最大的成本不是「找素材」而是「做动画/绑骨/调材质」。免费站（尤其 Kenney/Quaternius）的资产**质量稳定、风格统一、多数已绑骨带动画、导入即用**；AI 生成目前绑骨与动画仍不可靠，最适合做「静态物件」与「一次性特感模型」（特感动画可用程序化/混合动画）。

### 4.2 路线 A：免费资源站（主力）

| 站点 | 授权 | 适用资产 | 具体推荐 |
|---|---|---|---|
| **Kenney**（kenney.nl） | CC0 | 环境块、道具、UI、FPS 起步包 | `FPS Kit`、`City Kit`、`Prototype Kit`、`UI Pack`——质量与 Godot 兼容性一流 |
| **Quaternius**（quaternius.com） | CC0 | 低模角色、怪物、建筑 | `Ultimate Monsters`、`Ultimate Modular Buildings`、`Ultimate Animated Character` 等——**本项目的角色/丧尸主力来源** |
| **Poly Pizza**（poly.pizza） | CC0/CC-BY 筛选 | 聚合站，低模杂项 | 搜索 `low poly zombie/prop`，**只取 CC0**，CC-BY 要记署名 |
| **Mixamo**（mixamo.com） | 免费 | 绑骨 + 动画 | 所有角色动画集（idle/run/attack/die），非低模但**动画可通用** |
| **itch.io**（免费专区） | 看每包授权 | 各类 | 搜 `low poly zombie survival`，注意授权（要 CC0/MIT 的） |

> **下载后统一处理流程**：下载 → 解压 → 按 §3.0 命名规范改名 → 丢进 `assets/` 对应目录 → Godot 导入 → 检查比例（对门高 2.4m 校准）→ 材质换成统一 `StandardMaterial3D`（Flat Shading + 纯色/顶点色）。

### 4.3 路线 B：AI 生成（补缺口）

**工具链推荐**（按用途）：
- **Meshy.ai / Tripo 3D**：文生 3D / 图生 3D。生成低模网格 → 导出 `.glb`。适合特感、定制武器、氛围件。
- **Blockade Labs（Skybox）**：生成 360° 天空盒/远景环境，导出用于背景或远景件。
- **Blender + AI 辅助**：免费、全能。用 AI 生成 Python 脚本在 Blender 里批量建低模几何（如「生成一个低模汽油桶」的脚本），或用 AI 生成纹理后贴到简单几何上。

**AI 产出导入 Godot 的管线（关键步骤，缺一不可）**：
1. AI 生成（文生/图生）→ 下载 `.glb` 或 `.obj`。
2. 用 **Blender** 清洗：`Decimate` 减面到预算内（Modifier → Decimate → Collapse，Ratio 调到 tris 达标）；检查法线翻转（Edit Mode → Mesh → Normals → Recalculate Outside）；**统一 Y 轴向上、面朝 -Z**；必要时 `Merge by Distance` 清重复点。
3. 导出 `.glb`（勾选 `+Y Up`、仅选中对象）。
4. 拖入 Godot：`assets/` 对应目录。
5. 导入设置：勾选 Flat Shading；材质用项目统一材质（或保留顶点色）。
6. **比例校准**（对门高）→ 检查碰撞 → 入库。

> **注意**：AI 生成网格常见问题 = 面数超标、法线乱、非流形、比例奇怪。**每条都要在 Blender 里花 10-30 分钟清洗**，所以只用于「买不到/找不到」的缺口，不要全项目依赖 AI。

### 4.4 路线 C：CSG / 程序化（关卡原型）

- Godot 自带 `CSGBox3D` / `CSGCylinder3D` / `CSGPolygon3D` 等节点：**搭灰盒关卡**（房子、走廊、掩体）零成本、即时可见、带碰撞。MVP 阶段可直接用 CSG 灰盒 + 少量免费贴图跑起来。
- `GridMap` 节点：把模块化环境块铺成地图，性能好、改起来快。
- GDScript 程序化生成（扩展期）：用 `ArrayMesh` 在代码里生成简单几何（路灯、栅栏），AI 协作写脚本即可。
- **推荐流程**：MVP 用 CSG 灰盒验证玩法 → 扩展期把灰盒替换成 Kenney/Quaternius 模块块 → 打磨期补 AI 定制件。

## 5. 第一人称细节（Viewmodel / 命中反馈 / 丧尸差异化）

### 5.1 武器视口模型（Viewmodel）要点

- **结构**：View 模型挂到 `Camera3D` 子节点下（随相机移动），World 模型挂在玩家场景（其他玩家可见）。用 **渲染层（render layers）** 分离：view 模型只渲染到主相机层，world 模型从主相机层排除（避免穿墙穿模、避免重叠）。
- **不投阴影**：view 模型 `cast_shadow = OFF`（它离镜头太近，投影全是噪点还费性能）。
- **轻微晃动**：`sway`（鼠标移动时枪随动，幅度 2-5°）+ `bob`（行走上下晃动，幅度 1-3cm）——用手写 GDScript 平滑即可，不用弹簧物理。
- **FOV 处理**：武器 FOV 略高于世界 FOV（如世界 75°、武器 80°），缓解「枪太大/太小」的违和感；用 `Camera3D` 子相机的 FOV 偏移实现。
- **射击反馈**：开枪时 view 模型后坐（recoil）上抬 2-4°，0.1s 回弹；搭配枪口火光。

### 5.2 命中反馈视觉（Hit Feedback）

| 事件 | 视觉反馈 | 实现 |
|---|---|---|
| 命中敌人 | 血液粒子喷射 + 命中标记 | GPUParticles3D（见 §3.6）+ 准星旁 SVG「X」0.2s |
| 击杀 | 大血溅 + 尸体倒地 + 短时间 hitstop（暂停 0.05-0.1s） | 手感核心 |
| 命中特感 | 特感血条出现（HUD） + 更大血溅 | 特感比普通丧尸多血条 |
| 玩家受击 | 屏幕边缘红色渐晕 + 受击方向指示 | CanvasLayer 渐变贴图，随方向旋转 |
| 弹药不足 | 准星变色 + 点击空响（配 audio-director） | 准星由白转红 |

**准星设计**：静态 4 点准星（SVG）→ 移动/射击时扩散 → 命中时短暂「×」标记。三种状态一个材质三套 sprite，代码切。

### 5.3 低配下丧尸的视觉差异化（普通 vs 特感）

目标：**玩家 0.5 秒内分辨「这是普通还是特感、是哪只特感」**，不依赖高精度贴图。

| 维度 | 普通丧尸 | 特感 |
|---|---|---|
| 大小 | 同玩家（1.7-1.9m） | 明显不同：Hunter 更瘦矮、Tanker 更高更宽（2.2m+） |
| 颜色 | 病态暖灰/腐绿，与环境对比靠明度 | **高饱和强调色 + emissive 部位**：Hunter=青绿、Boomer=橙、Tanker=深红棕 |
| 剪影 | 常规人形 | 独特剪影：弓背/大肚/巨掌，见 §3.1 |
| 配饰 | 安全帽/破衣等小件 | 不加配饰，靠体型+颜色 |
| 特效 | 无 | 轻微 emissive 光晕（Boomer 脓包发光），特感出场时 HUD 图标提示 |
| 音效 | 嘶吼（audio-director） | 独特吼声（audio-director） |

> **MVP 保底方案**：普通丧尸用 2 网格 × 3 换皮 = 6 种外观 + MultiMesh 随机缩放/相位偏移，足以撑起 30 只同屏不显重复；特感先上 Hunter + Boomer 两只（模型可用 Quaternius 现成怪物改色）。

## 6. 可访问性（Accessibility）

**目标分级：Standard（标准级）**——对应特性矩阵，详见 `design/accessibility-requirements.md`（文策渊引用此分级）。

### 6.1 对比度规范（丧尸 vs 背景）

- **铁律**：丧尸表面亮度（L 值）比其 1m 范围内背景亮度 **至少高 25%**（用 HSL 的 L 计算，肉眼判断法：背景能看清时敌人一定更亮/更暖）。
- **落地手段**：环境色偏冷（蓝灰），敌人色偏暖（褐/黄褐）；敌人加微弱边缘光（rim light，方向光背光侧补一盏弱光或材质 emissive 极低值）。
- **道具对比度**：血包/弹药发光（emissive），在暗环境任何角度可见。

### 6.2 色盲友好的特感区分（不靠纯红）

- **铁律**：特感区分 = **形状 + 大小 + 非红色颜色 + HUD 图标** 四重冗余，任何单一通道失效仍可区分。
- 特感色不用纯红/纯绿对（红绿色盲最常见）：Hunter=青绿 `#3DDC84`、Boomer=橙 `#FF7A2F`、Tanker=深红棕 `#8A3A2E`（红棕与绿背景差异大，且有大体型+图标兜底）。
- 血液/受伤指示不单独用红色：玩家受击用「方向指示 + 渐晕」而非纯红；命中标记用白色「×」。
- **高对比模式（开关）**：开启后给丧尸加统一描边（outline shader），用黑白对比兜底。打磨期实现。

### 6.3 色盲模式 / 特性矩阵（对应 Standard 级）

| 特性 | 状态 |
|---|---|
| 色盲友好配色（非纯红区分） | ✅ 默认启用 |
| 高对比描边模式 | 🔶 打磨期（设置项） |
| UI 文本缩放（1x/1.25x/1.5x） | ✅ 设置项 |
| 减少闪烁（枪口光/爆炸频闪减弱） | ✅ 设置项 |
| 字幕/提示字号可调 | ✅ 设置项 |

### 6.4 UI 字号

- **基准（1080p）**：正文/提示 ≥ 18px；HUD 关键信息（血量/弹药）≥ 22px；任务目标 ≥ 24px；字幕 ≥ 24px。
- **缩放**：UI 用 Godot 的 `Control` + 主题字号变量，支持 1x-1.5x 缩放；字号设置存 `user://` 配置。
- 字体：Noto Sans CJK（免费，中文渲染好），嵌入子集控制体积。

## 7. 性能预算（配合 engineering-lead 的高密度丧尸方案）

> 目标平台仅 Windows（显卡范围宽），但仍按「低配可跑」设计，给局域网 4-8 人留出 CPU/带宽余量。**本段是给 engineering-lead 的硬约束，必须对齐。**

### 7.1 三角面与 Draw Call 预算

| 项 | 预算 |
|---|---|
| 全场景总三角面 | ≤ 500,000 tris（一屏内，100 只丧尸 + 环境） |
| 单个普通丧尸 | 500-1,200 tris（见 §3.1） |
| 同屏丧尸 | **MVP 30 只；扩展期常驻 60-80 / 峰值 100 只**（覆盖设计验收线 40） |
| 总 Draw Call | 目标 ≤ 150（Godot 4 Vulkan 前向渲染下轻松） |
| 材质变体总数 | ≤ 40 个共享材质（全项目） |

### 7.2 合批 / 实例化（给 engineering-lead 的关键约束）

1. **丧尸群用 MultiMesh**：同一种「网格+材质」的丧尸用 `MultiMeshInstance3D`（GPU 实例化），同材质 30-100 只 = 1 次 draw call。**约束：换皮必须只换材质 albedo_color，不换网格**（换网格 = 破合批）。普通丧尸走**顶点着色器动画**（无骨骼），MultiMesh 实例通过 `custom_data` 传相位偏移（防整群同步摆动）+ 随机缩放（0.9-1.15x，破重复感）。
2. **换皮 = 材质实例**：普通丧尸 6 种外观 = 1 网格 × 6 材质，全部走 MultiMesh（每个材质一个 MultiMesh 实例），6 个 draw call 承载 100 只丧尸。
3. **LOD**：普通丧尸因单只仅 500-1,200 tris、无骨骼，**不做几何 LOD**（GPU 成本已极低），用 `visibility_range` + Distance Fog 淡出即可；环境块/特感/玩家做 2 级 LOD 或距离剔除。
4. **距离剔除**：`visibility_range_begin` 设置——丧尸 60m、环境块 80m、远景件 200m；配合 Distance Fog 掩藏 pop-in。
5. **阴影**：主方向光只投近距离阴影（shadow distance ≤ 30m）；丧尸群**不投阴影或投 blob shadow**（圆形半透明黑贴花，成本极低）。枪口点光不投阴影。
6. **动画成本**：普通丧尸动画在顶点着色器内执行（GPU 侧，随实例化零 CPU 开销）；仅特感/玩家保留骨骼动画，且只对 15m 内的播骨骼、远的用 LOD 动画/冻结。
7. **尸潮出生**：用**对象池 + 分帧生成**（每帧生成 2-3 只），避免同帧大量实例化卡顿；尸体回收复用。

> **100 只同屏的可读性兜底（美术侧）**：数量越大单只越小，玩家靠「高饱和特感 + emissive」在尸潮中抓重点；普通丧尸用材质变体 + MultiMesh 随机缩放/相位破重复；远处丧尸被雾压暗，近处丧尸更亮——层次自然形成（§6 对比度仍按近处丧尸执行）。

### 7.3 网络同步与视觉（配合联机）

- 视觉上**只同步位置/朝向/动画状态机索引**，粒子与贴花是本地生成（谁看到谁生成），不同步——省带宽、防卡顿。
- 4-8 人各播各的本地特效，命中反馈由「服务器/主机确认命中」触发（视觉与判定解耦，避免延迟反馈）。
