## 0. 执行摘要（30 秒版）

1. **普通丧尸动画路线**（本清单最关键的决策）：**用 Quaternius 带骨骼模型 → Blender 剥离骨架 → 导出无骨骼静态 `.glb` + 代码 transform 摆动**。不播 100 个 AnimationPlayer（性能风险，技术方案 §5.1 判死刑），不强上顶点色 shader 动画（免费包无掩码，烘焙成本对 1 人团队不可行）。
2. **顶点色掩码方案**：标注为**打磨期可选**，仅在 AI 生成自定义丧尸时再烘焙（R=腿/G=臂/B=头躯干）。
3. **特感**：带骨骼 + AnimationPlayer，数量 ≤5 无性能压力，动画 ≤6（idle/walk/attack/hurt/death/spawn，缺的用最接近替代）。
4. **玩家**：第一人称只需手臂 + 武器；第三人称 Body 用静态人形（无动画，别人看足够）。
5. **优先级**：普通丧尸 > 特感 > 玩家 > 武器 > 地图 > 道具。
6. **最大风险**：带骨骼模型剥骨/减面/比例校准的 Blender 清洗量大，1 人无美术经验易卡壳 → 见 §5 降级预案。

## 2. 技术对齐（关键）

### 2.1 普通丧尸动画路线：三案权衡与推荐

**背景事实**：
- 美术方向 §3.1/§7.2 与 ADR-006 定案：普通丧尸 = 无骨骼 + 顶点色 shader 动画（R=腿/G=臂/B=头躯干掩码），走 MultiMesh 实例化。
- 技术方案 §5.1 明确：**每只一个 MeshInstance3D + 骨骼动画 = 100 次 draw call + 100 套骨骼 = ✗ 不可行**。
- M3-S4/S8 实测：100 只**独立实例 + 无骨骼 BoxMesh（无顶点动画）**CPU 帧时间 6.9ms 贴 idle 地板、physics 300/5s 无滞后 → **简化方案定案，MultiMesh 延后**。
- 现实约束：Quaternius/Kenney 免费包角色**多为带骨骼 .glb**，且**不带顶点色掩码**（顶点色掩码需在 Blender 烘焙，1 人无美术经验成本高）。

| 方案 | 做法 | 优点 | 缺点/风险 | 结论 |
|---|---|---|---|---|
| **A. 带骨骼模型 + 独立实例播骨骼动画** | 直接导入带骨骼 .glb，每只挂 AnimationPlayer | 动画自然、导入即用 | **100 个 AnimationPlayer + Skeleton3D 每帧更新 = CPU 大坑**（技术方案 §5.1 判死刑）；无法进 MultiMesh；实测基线（6.9ms）是不带动画的 BoxMesh，换骨骼动画后基线不成立 | ✗ 否决 |
| **B.（推荐）带骨骼模型 → 剥骨 → 无骨骼静态 .glb + 代码 transform 摆动** | Blender 删骨架仅留网格导出；AI 代码对 `Visual` 做整体 bob（`position.y += sin(t*8)*0.05`）+ 身体前倾 + 左右倾斜 + 相位随机（沿用 M3-S4 现状的位移摆动，升级为人形 + 配色） | ①与 MultiMesh 兼容（M3 后上 MultiMesh 零成本）；②CPU 成本 ≈ 现状（位置同步本来每帧写 transform）；③模型保留人形轮廓 + 铁律配色，可读性达标；④剥骨比烘焙掩码简单一个量级 | 行走观感不如骨骼动画自然（整体摆动，"飘着走"）——但 Low Poly + 尸潮密度下足够，M3-S4 现状已证明玩法可跑 | ✅ **推荐** |
| C. 无骨骼 + 顶点色 shader 动画 | 按美术方向烘焙顶点色掩码，shader 驱动腿部/手臂摆动 | 与 ADR-006 完全一致、GPU 侧零 CPU | **免费包无掩码 → 需 Blender 顶点绘制烘焙**，1 人无美术经验成本高、易返工；本阶段收益（CPU）已被 M3-S4 证明不必要 | 🔶 延后（打磨期可选） |

**推荐结论（明确）**：**方案 B——普通丧尸用带骨骼免费模型，但剥骨后导出为无骨骼静态 .glb，动画用代码 transform 摆动（bob/前倾/倾斜 + 相位随机），不播骨骼动画**。理由一句话：M3-S4 已实测 100 只独立实例无骨骼无动画 CPU 达标（6.9ms 贴地板），而 100 个 AnimationPlayer 是技术方案明确否决的性能风险；免费包无顶点色掩码使 shader 顶点动画本阶段不可执行；无骨骼静态网格与 MultiMesh 完全兼容，未来升级零成本。

**工程实现要点（给后续 Story / 程基岩）**：
1. **剥骨**：Blender 打开带骨骼 .glb → 选中 Armature 删除（保留 Mesh）→ 检查法线（Recalculate Outside）→ 导出"仅选中"无骨骼 .glb（+Y Up）。**不要手工合并顶点**（保留原拓扑，避免破坏换皮）。
2. **摆动动画**：在 `zombie_ai_common.gd` 的 `_physics_process` 对 `Visual` 节点做 transform 偏移即可（现状 BoxMesh 位移摆动的升级版）。**每实例相位随机**：用对象池 `custom_data` 或 `instance_id` 做种子，避免整群同步（美术方向 §7.2 要求）。**摆动幅度小**（位移 ±5cm、倾斜 ±4°），避免穿模/违和。
3. **死亡表现**：沿用现状"倒地淡出 + 血雾"（技术方案 §5.1 第 5 条：不做布娃娃）。
4. **MultiMesh 未来切换**：模型已无骨骼 → 将来把 `Visual` 从 MeshInstance3D 换成 MultiMeshInstance3D 时，仅需改实例 transform 写入路径，**模型与材质可直接复用**。

### 2.2 顶点色掩码：替代方案

- **免费包模型无掩码** → 本阶段**不执行**顶点色 shader 动画（方案 C 延后）。
- **替代**：代码 transform 摆动（见 2.1 方案 B），不依赖顶点色。
- **顶点色用途修正**：若免费模型自带顶点色（Quaternius 部分模型有），保留用于**明度层次**（顶面亮、底面暗），提升立体感；**禁止**用作动画掩码（无掩码语义）。
- **打磨期可选**：若引入 AI 生成自定义丧尸，再按美术方向 §3.1 烘焙掩码（R=腿/G=臂/B=头躯干），届时走方案 C 提升动画质量——**记入 P2 打磨，不阻塞本阶段**。

### 2.3 特感：带骨骼 + AnimationPlayer（数量 ≤5，无性能压力）

- 技术方案 §10.1：2000-4000 tris、标准骨骼、动画 ≤6。
- **动画槽位统一命名**：`idle / walk / attack / hurt / death / spawn`。Quaternius 免费包自带动画名/数量可能不符：
  - `idle`/`walk`/`attack`（或 attack 用 bite/swipe 类）/`death`（die）通常有；
  - `hurt` 缺 → 用 `idle` 加轻微后仰（代码）或复用 attack 前摇替代；
  - `spawn` 缺 → **用淡入替代**（节点 `visibility`/材质 transparency 从 0 渐显 0.5s），不做 spawn 动画槽。
- 动画名统一映射在 **AnimationPlayer 资源内重命名**（Blender 或 Godot 导入后），避免脚本硬编码错名。
- 数量上限：同屏特感 ≤5（director.json 配额），**独立实例化、不池化**（M3-S4 定案）。

### 2.4 玩家（≤3000 tris）

- **第一人称**：只需手臂 + 武器（view 模型），挂在 Camera3D 子节点（美术方向 §5.1），不投阴影。
- **第三人称 Body**（`player.tscn/Body`，别人看）：静态人形即可，**无动画**（省成本；远端玩家已有 20Hz 位置插值，静态身体足够）。如免费包带动画且零成本，可加一个 idle 呼吸动画，但不强求。
- **注意**：玩家 Body 是第一人称自己看不到的（相机在 Head y=1.6），所以 Body 用最简单模型即可，不为其做骨骼动画。

### 2.5 材质 / 贴图纪律（全资产统一）

- 一律 `StandardMaterial3D`，**Flat Shading 开**（Mesh 导入时勾选或材质开启）；纯色 `albedo_color` + 可选顶点色。
- **单纹理、禁 PBR 多层**（技术方案 §10.1：不引法线/粗糙度/金属度贴图）；贴图一律 2 的幂（256/512/1024），import 开 VRAM Compressed。
- 半透明/发光材质 ≤5 个（血包/弹药 emissive、特感脓包、区域板）。
- 每模型 ≤2 种材质（美术方向铁律 3）。
- 敌人明度铁律：丧尸表面 L 比 1m 内背景高 ≥25%（美术方向 §6.1）；远处靠 Distance Fog 压暗、近处亮 → 用材质变体/顶点色做层次，不靠贴图。

### 2.6 与既有文档的冲突标注（对齐结论）

| 冲突点 | 美术方向（原） | 技术方案 / 实测（现） | 对齐结论（以可执行为准） |
|---|---|---|---|

### 4.1 铁律：保持节点结构，只换 Mesh / 材质

> 所有替换的目标是「**视觉替换**」，**不碰碰撞、不碰逻辑、不碰网络**。现有结构：`StaticBody/CharacterBody → (MeshInstance3D/Visual/Body) + CollisionShape3D + AI/Health/Sync`。

### 4.2 逐场景注意点

1. **普通丧尸（R1/R2）**：`Visual` 是 MeshInstance3D（非 MultiMesh），**本阶段不换节点类型**（MultiMesh 延后）；代码摆动动画加在现有 `_physics_process` 对 Visual 的 transform 上，**不要新增 AnimationPlayer 节点**（违反 §2.1 结论）。
2. **换皮（R3）**：材质变体 = 复制 `StandardMaterial3D` 改 `albedo_color`，**同一 .glb 网格 + 多材质实例**，不复制网格（保合批铁律）。
3. **特感（R4/R5）**：根节点名 `Charger`/`Spitter` 不改；`Visual` 需挂 `AnimationPlayer`（**特感场景新增，普通丧尸不加**）；动画名统一为 6 槽（§2.3），spawn 缺失用淡入。
4. **武器**：view 模型 `cast_shadow = OFF`、渲染层分离（view 只渲染主相机、world 从主相机层排除）——这是**视觉层配置**，脚本的 `muzzle_offset`（`weapons.json`）不动；若 view/world 模型与枪口位置不符，只调 ViewMesh/WorldMesh 的本地 position，不改 `weapons.json`。
5. **环境**：模块块尺寸若与原 BoxMesh 差异大（如墙厚 0.5 vs 模块 0.6），**优先微调 Mesh 的 position/rotation，不调 Collision**（碰撞保持原语义，避免导航/射线行为变化）；若必须改 Collision 尺寸，需重跑冒烟测试（导航、丧尸撞墙、玩家移动）。
6. **道具**：emissive 材质数量控制（半透明/发光 ≤5）；血包医疗绿、弹药黄/橙（§1.4 修正），**这是从蓝/红改色，需确认 supply_point.gd/pickup_item.gd 无颜色依赖**（应为纯视觉，脚本只切 visible）。
7. **替换顺序**：按优先级 P0→P4 逐场景替换，**每个场景替换完跑一次冒烟测试**（`tests/` 冒烟清单），再进下一个——禁止一次全换（技术方案 §8.1 黄金闭环：一个小目标一个 commit）。

### 4.3 工程实现要点汇总（交接给程基岩）

- 普通丧尸：**不加 AnimationPlayer**；transform 摆动（bob/前倾/倾斜 + 相位随机种子）写在 `zombie_ai_common.gd`（或独立小脚本），仅服务器执行，客户端快照插值显示（技术方案 §4.2 同步策略不变）。
- 特感：新增 AnimationPlayer，动画名 6 槽，spawn 淡入。
- 玩家：Body 静态；武器 view/world 节点新增。
- MultiMesh：延后（M3-S4 定案）；本清单所有模型已保证无骨骼 → 未来兼容。
- 性能复测：P0 普通丧尸替换后，用 `tools/debug_pool_perf.gd` 复测 30/60/100 档（沿用 M3-S4 方法学），确认仍贴 6.9ms 地板。

## 附录 B：Blender 清洗速查（每模型 10-30 分钟）

1. 导入 .glb（File → Import → glTF 2.0）。
2. **剥骨（仅普通丧尸）**：Outliner 选中 Armature → X 删除 → 保留 Mesh。
3. **减面**：选中 Mesh → Modifiers → Add Modifier → Decimate → Collapse → Ratio 调到 tris 达标（查看 Stats：右上角 3D Viewport Overlays → Statistics）。
4. **修法线**：Edit Mode（Tab）→ A 全选 → Mesh → Normals → Recalculate Outside。
5. **清重复点**：Edit Mode → Mesh → Clean Up → Merge by Distance（Distance 0.001）。
6. **比例校准**：角色底部对齐 Y=0，身高对齐 1.8m 参考立方体（可拉一个 1.8m 高 box 比对）；门高 2.4m。
7. **面朝 -Z**：角色/武器前方对 -Z（Godot 约定）。
8. **导出**：选中对象 → File → Export → glTF 2.0 → 勾选 `+Y Up`、`Selected Only` → 导出 .glb。
9. **Godot 导入**：丢入 `assets/models/<子目录>/` → Import 面板勾选 Flat Shading（如网格带平面法线可跳过）→ 材质统一 StandardMaterial3D 纯色/顶点色。
