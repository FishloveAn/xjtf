# 代码核对与修复报告（2026-08-07）

## 结论

DeepSeek 已实现大部分单机玩法和双实例联机骨架，但此前“全部完成、全部通过”的结论不可靠：实际存在出生方向错误、安全屋无法按直觉离开、联机生成竞态、同步器初始化过晚、多人出生重叠弹飞、敌人直线顶墙、存档不能真正恢复，以及测试脚本假阳性等问题。本轮已完成三批修复：首轮阻断问题与测试可信度修复，普通怪/特感寻路、中途续玩存档、本机 4–8 人并发联机验证和性能基线，以及 Director 降级上限、8 人加 100 怪压力与 10 局加速稳定性验证。

## 本轮已修复

- 玩家出生点朝向生效，单机出生后按 W 可直接朝安全屋出口移动。
- 调整安全屋开门触发范围，输入行走可真实触发开门和第一波尸潮。
- 出生点从 2 个补齐为 8 个；按连接 peer 排序分配，避免随机 peer id 取模导致玩家重叠并被弹到高空。
- 联机主场景增加“全部客户端就绪后再生成玩家”的握手，避免 Spawner 包在客户端切场景时丢失。
- 初始关卡阶段不再在切场景竞态窗口发送 RPC。
- Player、Health、Weapon、普通丧尸和特感的 MultiplayerSynchronizer 改为入树阶段配置，消除复制启动时未配置错误。
- 无网络 peer 时的服务器判断改为单机语义，避免断开瞬间反复报错。
- 修复玩家输入测试的方向判断、固定端口冲突、字符串格式错误和 headless 鼠标假失败。
- 修复波次测试 300 秒空跑且超时仍返回成功的问题。
- 修复联机运行器“0 PASS / 0 FAIL 也返回成功”、错误 Bash、残留标记串场和进程提前强杀等问题。
- 普通怪接入 `NavigationAgent3D` 和 Rustyard 预烘焙导航网格；无导航网格的旧场景保留有限墙碰撞绕障。
- 安全门不参与静态导航烘焙，实体门关闭时阻挡，开门后路径立即连通。
- 对象池复用的普通怪会清理绕障状态并重新计算路径。
- 冲撞者和喷吐者复用 Rustyard 导航网格进行复杂障碍追击；技能增加真实世界 LOS 门槛，隔墙不会蓄力冲撞或吐酸，取得有效直线后仍保留冲撞和酸池语义。
- 存档升级为 v3，保存关卡阶段、主机位置、朝向、生命/状态、当前武器、四把枪当前弹匣和关键关卡标志；v1/v2 存档可迁移。
- 主菜单新增“继续存档（创建主机）”；普通建房/加入明确按新游戏启动，不会误读旧档。
- 损坏、结构不完整或未知版本存档不会显示为可继续；主机存档每局只消费一次。
- 写盘采用临时文件校验后替换，并保留 `.bak` 最近有效档；主档损坏时可恢复备份，导航网格外的不安全位置会被拒绝。
- 调试与压测脚本使用隔离存档路径并清理测试档，不再改写正式 `user://save/progress.json`。
- `director.json` 的 degrade 已真正参与 WaveManager 总同屏上限：普通怪和特感共同受限；关闭时不干预原波次配置，非法非正值会明确告警并安全限制为 1。
- 音效系统改为 `audio_events.json` 事件表驱动，55 个事件支持多变体、变调、音量、距离、总线与同帧限流；现有素材播放和预留素材静默路径通过专项回归。

## 已验证

- 输入到战斗闭环：按 W 行走约 5.9 秒触发第一波，怪物自然追击并造成 10 点伤害。
- 双实例联机：44 PASS / 0 FAIL，覆盖玩家互见、出生贴地、位移同步、怪物复制/回池、补给、伤害、倒地、救援、主机退出和客户端断线。
- 三波竞技场通关、推进关卡全流程、武器、冲撞者、喷吐者、掉落、音频、对象池与 100 只 headless CPU 压测通过。
- 固定帧加速连续 10 局自动化通关，十局稳定点节点计数均为 279、波动 0；退出时 ObjectDB 泄漏与未释放资源均为 0。标准时钟连续完成 7 局并进入第 8 局后受外部 186 秒工具上限终止，不能替代真实长局。
- 全脚本加载、全场景实例化通过。
- 寻路回归：普通怪可穿门、绕墙并在归池后重建路径；冲撞者/喷吐者在 SafeEastA 两侧均取得 50 点复杂路径，隔墙不放技能，绕至 LOS 后分别实际冲撞命中和生成酸池。
- 存档回归：v3 写读、v1/v2 迁移、主档损坏回退 `.bak`、阶段边界自动存档、重建主场景恢复中途阶段/安全位置/生命/武器/弹匣/关卡标志均通过；完成档恢复至可活动的 BACKDOOR 休整区并只触发一次结算，新游戏忽略旧档。
- 本机回环并发：4 人合计 53 PASS / 0 FAIL，8 人合计 109 PASS / 0 FAIL；各端看到全部玩家，peer 和 8 个出生槽唯一，出生快照一致，并观察到客户端权威位移。该结果不是双机或真实网络验收。
- 本机 8 人加 100 怪压力专项：152 PASS / 0 FAIL / 0 Godot 错误；8/8 端复制 100 怪，正式伤害击杀与对象池回收被全部端观察，批量回收后 Zombies=0、池 active=0，退出后无残留进程。
- 窗口性能基线：100 怪整帧平均 5.00ms、P95 6.95ms；draw call 平均 86.84、P95 144；Godot 跟踪渲染内存约 125.53MB。
- 网络基线：100 怪向一个客户端稳定同步约 79KB/s；当前数据不支持立即实施 MultiMesh、自定义快照或兴趣管理。
- Windows Release 重新导出并通过 headless 启动冒烟：EXE 109,081,088 字节，PCK 3,257,516 字节；导出预设已排除项目文档，避免概念图等开发资料进入正式包。

## 仍未完成或未充分验证

- Windows 导出包尚未完成真实窗口人工操作验收；本轮窗口自动化因系统窗口句柄失效无法执行。
- 尚未用两台真实电脑验证局域网、防火墙、不同帧率和真实网络抖动；当前证据包含本机双实例功能流及本机 4/8 进程回环并发，不包含真实网卡、丢包、重传或不同设备帧率。
- 已完成本机 4 人和 8 人 headless 的入场、唯一出生槽、全端快照一致、单客户端位移，以及 8 人加 100 怪复制/单次击杀/批量回收短测；尚未完成两台以上真实电脑、真实局域网、防火墙/抖动，以及 4–8 人完整枪战/掉线重连长局。
- “10 局 × 20 分钟”仍未完成；当前完整 10 局属于固定帧加速验证，标准时钟只完整跑完 7 局并进入第 8 局，不能替代人工长局。
- 已测窗口整帧、draw call、引擎跟踪显存和本机 ENet 字节；GPU 单帧耗时、真实设备总显存、双机丢包/抖动仍未测。
- 普通怪、冲撞者和喷吐者已接入当前 Rustyard 导航网格；墙体布局变化后仍必须重跑离线导航生成和三类敌人导航回归。
- 当前仍只有一个段落；完成档会恢复到可活动的 BACKDOOR 休整区并显示一次结算，但没有下一关内容。
- 存档仍不序列化活跃敌人、弹道、掉落物和完整动态世界，只以阶段/触发标志在干净世界重启必要波次；仍只保存主机状态，弹药只含当前弹匣，不含客户端独立状态或备用弹药。
- `director.json` 的 degrade 总同屏限制已实现；MultiMesh、自定义快照和兴趣管理仍未实现，目前也没有必须立即实施的本机性能证据。
- 投掷物、主机迁移、客户端预测、更多玩家外观属于明确砍掉或延后的范围。
- 枪声音源仍有占位素材，玩法数值与掉落概率仍标注为待平衡。
