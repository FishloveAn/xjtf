# 阶段六 · 维护（阶段说明文档）

> 阶段序号：06 ｜ 阶段名称：维护 ｜ 所属项目：《星际土匪》（StarBandit, L4D-like）
> 本文件说明：本阶段要做什么、输入输出、负责人、验收标准。

## 1. 本阶段目标

项目交付后的小版本迭代与问题修复。本作是**局域网本地游戏、无在线服务**，维护面天然很小，重点在：Bug 修复、平衡调整、内容扩展、引擎升级管理。

## 2. 任务清单

- [ ] T6.1 Bug 修复流程（缺陷记录 → 分级 → 修复 → 回归冒烟）
- [ ] T6.2 平衡调整（武器/丧尸数值，走 `data/weapons.json`、`data/zombies.json` 数据表）
- [ ] T6.3 内容扩展（新武器/新特感/新地图，遵守数量硬上限：武器 ≤5、特感 ≤3）
- [ ] T6.4 引擎升级管理（升级前全量跑冒烟清单，参考 `03-开发-引擎版本记录.md`）
- [ ] T6.5 素材署名维护（`CREDITS` 持续登记，CC-BY 素材不遗漏）

## 3. 输入 / 输出

| 类型 | 文件 |
|------|------|
| 输入 | 玩家/开发者反馈、缺陷记录 |
| 输出 | 修复后的代码版本 + 更新后的冒烟结果 |
| 输出 | 补丁说明（版本号 + 变更清单） |

## 4. 负责人

| 角色 | 成员 | 职责 |
|------|------|------|
| 修复/平衡 | 程基岩（engineering-lead） | 代码修复、数值调整 |
| 回归验证 | 严守真（quality-lead） | 回归冒烟 |
| 版本管理 | 路远行（release-ops-lead） | 版本号、变更日志 |
| 决策 | 用户（开发者） | 优先级拍板 |

## 5. 验收标准

1. 每个修复有对应回归验证记录
2. 数据调整不触碰代码（JSON 数据驱动原则）
3. 升级引擎或改架构前，全量冒烟清单通过
