# 阶段四 · 测试（阶段说明文档）

> 阶段序号：04 ｜ 阶段名称：测试 ｜ 所属项目：《星际土匪》（StarBandit, L4D-like）
> 本文件说明：本阶段要做什么、输入输出、负责人、验收标准。

## 1. 本阶段目标

用"验证驱动开发"思想，在每个里程碑交付时用可执行的冒烟清单验证"能跑什么、验证什么"，将缺陷挡在进入下一里程碑之前。1 人团队不做自动化单元测试，以冒烟清单 + Playtest 为主。

## 2. 任务清单

- [x] T4.1 M0 冒烟清单编写（A 单机 / B 联机两组，C 记录边界）
- [ ] T4.2 **M0 实测**（用户跑 A 组，等待中）
- [ ] T4.3 M1 冒烟清单（战斗闭环：开枪/换弹/命中/丧尸受击/死亡）
- [ ] T4.4 M2 冒烟清单（波次完整流程 + 联机全流程）
- [ ] T4.5 M2 性能压力测试（30→50→100 丧尸帧率曲线）
- [ ] T4.6 Playtest ≥1 轮（M2 后，4 人局域网真实试玩）

## 3. 输入 / 输出

| 类型 | 文件 |
|------|------|
| 输入 | 各里程碑交付的运行代码 |
| 输出 | `04-测试-冒烟测试清单.md`（本目录，随里程碑扩展） |
| 输出 | 缺陷记录（Bug 分级：致命/严重/一般/轻微，后续由 quality-lead 规范） |

## 4. 负责人

| 角色 | 成员 | 职责 |
|------|------|------|
| 测试策略 | 严守真（quality-lead） | 测试计划、用例、冒烟、回归 |
| 实测执行 | 用户（开发者） | 按清单逐条验证、报错回传 |
| 修复 | 程基岩（engineering-lead） | 依据缺陷记录修复 |
| 质量门判定 | 游承峰（主理人） | 里程碑验收 PASS/CONCERNS/FAIL |

## 5. 验收标准

1. 每个里程碑交付时附对应冒烟清单（✅ 流程已建立）
2. M0 A 组全过才进 M1（⏳ 等用户实测）
3. M2 前性能压力测试有记录（未开始）
4. 致命/严重 Bug 清零才允许进入下一里程碑（未开始）

## 6. 当前状态

**测试体系已建立，M0 冒烟等待用户实测**。请用户用 Godot 4.7.x 打开项目，逐条跑 A 组（A1-A7），结果回传主理人。
